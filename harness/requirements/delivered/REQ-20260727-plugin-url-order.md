# REQ-20260727 Plugin URL Matching Order

## 状态

Delivered

## 原始需求

1. 计算每次插件 `canParseUrl` 的调用时长；超过 1 秒的插件按耗时长短调整调用顺序，未超过 1 秒的插件保持原顺序。
2. 命令行指定插件时也需要处理短链接跳转。

## 需求分析与验收标准

- 每次 URL 候选检查均采集并记录 `canParseUrl` 耗时。
- 最近一次耗时不超过 1 秒的插件保持插件快照中的原始相对顺序。
- 最近一次耗时超过 1 秒的插件排在普通插件之后，并按耗时从短到长排列。
- 首次调用尚无耗时数据时完全保持原快照顺序；耗时数据只在当前进程内生效。
- 自动选择插件时继续执行“原始 URL 优先、Location URL 兜底、首个匹配插件胜出”的流程。
- 命令行指定插件后，如果该插件不能解析原始 URL，则取得 HTTP Location，并使用跳转 URL 调用 `getVideoView`。
- 指定插件即使不声明支持原始 URL 或跳转 URL，也保持原有强制选择语义。

## 设计评审结论

- 排序状态放在客户端 `PluginInterface`，不修改第三方插件接口，因此没有插件 API/ABI 或配置迁移影响。
- 使用 `steady_clock` 避免系统时间调整影响耗时计算；使用互斥锁保护并发 URL 解析任务共享的耗时状态。
- 普通插件通过稳定排序保持相对次序；慢插件后置并按耗时升序排列。

## 落地结果

- `PluginInterface::parseUrl` 支持可选的指定插件 ID，并统一执行短链接探测。
- `PluginInterface` 增加候选顺序计算、调用计时和结构化日志。
- CLI 改为统一调用 `parseUrl`，不再通过 `getPlugin` 绕过短链接处理。
